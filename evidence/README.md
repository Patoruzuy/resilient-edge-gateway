# Evaluation Evidence

This folder contains the evaluation evidence from the Raspberry Pi assessment.

## Datasets used

The EMA analysis is based on 15 runs:

- `DIRECT-BASE-r1`
- `DIRECT-BASE-r2`
- `DIRECT-BASE-r3`
- `GATEWAY-BASE-r1d`
- `GATEWAY-BASE-r4`
- `GATEWAY-BASE-r3`
- `DEG-100MS-10LOSS-r2`
- `DEG-100MS-10LOSS-r3`
- `DEG-100MS-10LOSS-r4`
- `OUT-15S-2HZ-r4`
- `OUT-15S-2HZ-r2`
- `OUT-15S-2HZ-r3`
- `OUT-30S-5HZ-r1`
- `OUT-30S-5HZ-r2`
- `OUT-30S-5HZ-r3`

For each run, there is evidence available regarding the publisher, gateway, collector, impairment, storage, and reconciliation.

Other folders include preflight, diagnostic, or anomalous runs. These are kept as project evidence but are not part of the final quantitative analysis.

The text files in this folder are generated by pytest and git output just before the merge.
Evidence format: Evidence name - Number of messages - Evidence number

baseline-50-1
baseline-50-2

## Preflight and diagnostic runs

Preflight, diagnostic, failed and anomalous runs are retained as project evidence but are not included in the final statistics.

They document how the evaluation method was tested and corrected.

- `baseline-050-001`
- `duplicate-evidence-001`
- `PRECHECK-GATEWAY-001`
- `PREFLIGHT-COLLECTOR-BURST-001`
- `GATEWAY-BASE-r1-failed`

## Run evidence

Depending on the scenario, a run directory may contain:

- `publisher_output.csv`
- `gateway.db`
- `evaluation.db`
- `reconciliation.csv`
- `summary.json`
- `timeline.csv`
- `recovery_metrics.json`
- `storage_samples.csv`
- NetEm or supporting diagnostic evidence

The EMA contains the analysis. This directory contains the supporting evidence.
